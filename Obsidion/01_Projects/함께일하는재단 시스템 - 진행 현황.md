## 🌐 실행 방법

```
cd web
npm run dev
```

| 화면 | 주소 |
|---|---|
| 👤 참여자 | `http://localhost:3000` |
| 🔐 관리자 | `http://admin.localhost:3000` |

> [!warning] 주소가 완전히 분리되어 있습니다
> 서로 오가는 버튼이 없습니다. 참여자 주소에서 `/admin` 을 쳐도 **404**.
> 의뢰자는 관리자 주소를 모른 채 참여자 화면만 시연하면 됩니다.
> 실서비스에서는 `www.도메인.kr` / `admin.도메인.kr` 로 그대로 이어집니다.
>
> ⚠️ 지금은 로그인이 없어 **주소를 아는 사람은 관리자 화면에 들어올 수 있습니다.** 실제 방어선은 로그인 붙일 때의 권한 검증입니다. 주소를 숨기는 건 보안이 아닙니다.

## ⏸ 보류된 결정

> [!question] 플랫폼 — Supabase vs Firebase
> **쟁점은 카카오 로그인.** Firebase Auth는 카카오를 공식 지원하지 않아 Cloud Functions(종량제) 또는 Identity Platform(유료)이 필요하다. Supabase는 기본 지원.
> ⚠️ Firebase Storage도 신규 프로젝트는 종량제 플랜을 요구 → **"무료라서 Firebase"가 성립하지 않을 수 있음.**
> ↔️ Supabase 단점: 무료 플랜은 **1주일 미접속 시 자동 정지** (버튼으로 복구, 데이터 유지).

> [!question] 도메인
> 미구매. 개발은 `localhost` 로 진행.
> 권고: `.or.kr`(법인서류 필요) → `.kr` → `.org`/`.com` · 구매처 가비아 / Cloudflare
